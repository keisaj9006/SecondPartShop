## Permissions and 16 KB inspection

The actual merged manifest declares six permissions: INTERNET, ACCESS_NETWORK_STATE, POST_NOTIFICATIONS, WAKE_LOCK, Google C2DM RECEIVE, and the app-specific signature-protected DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION. No camera, location, microphone, broad storage, media-library, contacts or SMS permission is declared. The evidence JSON counts only the four `android.permission.*` entries; the separately retained complete permission report and independent manifest include all six. Permission absence does not establish absence of data collection.

The AAB requests `PAGE_ALIGNMENT_16K` and uncompressed native libraries. It contains 12 `.so` files: DataStore shared counter, CameraX image processing and CameraX surface utility for arm64-v8a, armeabi-v7a, x86 and x86_64. Actual dependency metadata identifies DataStore 1.1.7 and CameraX camera-core 1.4.2; pinned Camera 8.2.4 brings ioncamera-android 1.0.2. Camera 8.2.5 still references the same native dependency, so no speculative update was applied.

All 12 files pass LOAD alignment at least 0x4000, offset/address congruence and non-overlapping 16 KB LOAD pages. 11 RELRO ends are not raw 16 KB multiples; all 12 RELRO regions cover the entire corresponding writable LOAD. The initial blanket modulo-based blocker was withdrawn after examining the [Android 16 QPR2 loader](https://android.googlesource.com/platform/bionic/+/android16-qpr2-release/linker/linker_phdr_16kib_compat.cpp) and [Android 17 loader](https://android.googlesource.com/platform/bionic/+/refs/heads/android17-release/linker/linker_phdr_16kib_compat.cpp): this layout is explicitly exempt from the unsafe writable-suffix alignment rule. Original [Android 15](https://android.googlesource.com/platform/bionic/+/refs/heads/android15-release/linker/linker_phdr.cpp) and [Android 16](https://android.googlesource.com/platform/bionic/+/refs/heads/android16-release/linker/linker_phdr.cpp) whole-segment protection behavior was also inspected. This states the loader predicate precisely; it does not claim every RELRO passes the guide's simplified modulo check.

A universal analysis APK was generated from that exact AAB with a new local ephemeral analysis signer. SHA256 `5c3748f551a18918e06f61c671bf3cdeff628b129b3dd423d982409f44d37a79`; SDK 36 `zipalign -c -P 16 -v 4` returned `Verification successful`, exit 0. It is not a Play release artifact.
